# Contract: お気に入りの画面構成と HTML の枠

**Feature**: 002-favorite-locations | **Date**: 2026-10-05

ルート・URL・ステータスコードは 001 の [web-routes.md](../../001-marine-forecast-view/contracts/web-routes.md) から変更しない。
お気に入りのためのルート・API は作らない（FR-010。お気に入りの内容をサーバーに送らない）。
この文書は、Twig が出力する「枠」と JavaScript の間の取り決め、および画面構成を定める。画面設計は人間のレビュー対象。

## トップ画面（`GET /`）の構成（上から順）

1. タイトル「UMIYOMI」とリード文
2. 緯度・経度の入力フォーム（001 のまま）
3. **お気に入り**（見出し「お気に入り」。折りたたまない）
   - 端末内保存の注意書き（FR-012）：「お気に入りはこの端末のこのブラウザにだけ保存され、他の端末とは共有されません。ブラウザのデータを消去すると消えます。」
   - 0 件のとき（US1-6）：「お気に入りはまだありません。予報画面で表示中の地点を保存できます。」
   - 一覧（新しく保存したものが上）。各項目：
     - 表示名と座標（`北緯 27.75° / 東経 129.05°`）を含む、予報画面へのリンク
     - 「名前を変更」ボタン → 項目がその場で入力欄（現在の名前入り、空の名前なら空欄＋プレースホルダに座標）と「保存」「キャンセル」に切り替わる
     - 「削除」ボタン → 確認（`window.confirm`）のあと削除
   - 予報の数値・海況の判定は表示しない（FR-013）
4. フッター（001 のまま）

## 予報画面（`GET /forecast`）の構成（上から順）

1. タイトルと入力フォーム（001 のまま）
2. **お気に入り一覧（折りたたみ）**：`<details>`（`open` なし）。`<summary>` は「お気に入り（3 件）」
   - 開くと、項目ごとに予報画面へのリンク（表示名と座標）。名前変更・削除のボタンは置かない（FR-016）
   - 表示中の地点の項目は `aria-current="page"` を付け、「表示中」と表示する（FR-005）
   - 端末内保存の注意書き（FR-012）と、0 件のときの案内
3. 警告（001 のまま）
4. 地点・最終更新（001 のまま）
5. **お気に入りの保存パネル**（入力エラー 422 のときは出さない。503 / 429 / Stale でも出す）
   - 未保存：名前の入力欄（ラベル「名前（省略可・30 文字以内）」、プレースホルダ「例：27.75, 129.05」）と「お気に入りに保存」ボタン
   - 保存済み：「お気に入りに保存済み：テスト沖」と「お気に入りから外す」ボタン（確認のあと削除。FR-016 の例外）
   - 保存・削除のあとは、パネルの表示と 2. の一覧（件数を含む）をその場で更新する。結果は `role="status"` の領域で知らせる（US1-1「保存できたことが画面上で分かる」）
6. 注意書き以降（001 のまま）

## 状態ごとのメッセージ

| 状態 | 文言 | 表示場所 |
|---|---|---|
| 保存した | 「お気に入りに保存しました」 | 保存パネル（`role="status"`） |
| 外した | 「お気に入りから削除しました」 | 保存パネル（`role="status"`） |
| 名前が 31 文字以上 | 「名前は 30 文字以内で入力してください」 | 名前の入力欄の下（`aria-invalid` と `aria-describedby`） |
| 20 件ある | 「お気に入りは 20 件まで保存できます。トップ画面の一覧で不要なお気に入りを削除してから保存してください」 | 保存パネル |
| `setItem` が失敗 | 「お気に入りを保存できませんでした。ブラウザの設定や空き容量を確認してください」 | 保存パネル・トップ画面の一覧 |
| localStorage が使えない／JavaScript が無効 | 「この環境ではお気に入りを保存・表示できません。緯度・経度を入力すれば予報は表示できます。」 | お気に入りの枠（トップ画面の一覧・予報画面の折りたたみ一覧・保存パネル） |
| 削除の確認 | 「『{name}』をお気に入りから削除しますか？」 | `window.confirm` |

- 安全・出航可否を断定する表現（「安全です」「出航できます」「問題ありません」）を含めない（FR-013、原則 IV）
- 重複保存は、保存済みの地点では保存フォームを出さないことで防ぐ。別タブで保存済みになっていた場合は、保存時に読み直して保存済みの表示に切り替える

## Twig と JavaScript の取り決め

JavaScript（`assets/app.js` から読み込む `assets/favorites/favorites-ui.js`）は、次の要素があるときだけ動く。どれもなければ何もしない。

| 要素 | 出力する画面 | 役割 |
|---|---|---|
| `[data-favorites="manage-list"]` | トップ画面 | 名前変更・削除ができる一覧の枠 |
| `[data-favorites="switch-list"]` | 予報画面 | 選んで開くだけの一覧の枠（`<details>` の中） |
| `[data-favorites="count"]` | 予報画面 | `<summary>` 内の件数 |
| `[data-favorites="save-panel"][data-latitude][data-longitude]` | 予報画面（422 以外） | 保存パネル。座標は `'%.2f'` の文字列（例：`27.75`） |
| `[data-favorites-state="…"]` | 各枠の中 | `hidden` 付きで出力し、JavaScript が状態に応じて 1 つだけ表示する（`unavailable` / `empty` / `ready` / `saved` / `unsaved`） |
| `[data-favorites-message="…"]` | 各枠の中 | `hidden` 付きのメッセージ（`saved` / `removed` / `name_too_long` / `limit` / `write_failed`） |
| `<template data-favorites-template="manage-item">` 等 | 各画面 | 一覧の項目の HTML。JavaScript は複製して `textContent` / `href` / `value` だけを設定する |
| `data-confirm-remove="『{name}』をお気に入りから削除しますか？"` | 各枠 | 削除確認の文面のひな形 |

- 初期状態（JavaScript 実行前）は、すべての状態要素が `hidden`。`<noscript>` で「使えない」の文言を出す
- 名前を HTML として解釈させない（`innerHTML` を使わない。research R5）
- お気に入りの処理で例外が起きても、予報の表示（サーバー側の HTML）には影響しない
