# Feature Specification: アクセス解析の導入

**Feature Branch**: `006-analytics-tag`
**Created**: 2026-10-05
**Status**: Draft
**Input**: User description: "アナリティクスタグを入れたい"

## Clarifications

### Session 2026-10-05

- Q: どのアクセス解析を使うか？ → A: Google アナリティクス（GA4）を使う。Cookie で利用者を識別し、再訪・経路・操作まで分析できる方式とする（FR-003）
- Q: 計測する範囲は？ → A: 画面の閲覧に加えて、主要な操作（お気に入りの保存・削除、現在地ボタン、フィードバックフォームを開く）の回数も記録する（FR-004）
- Q: 予報画面の緯度・経度を送るか？ → A: そのまま送る。どの海域がよく見られているかを分析に使う。ただし利用者が自由に入力した文字列とお気に入りの名前は送らない。送ることは外部送信の案内で明示する（FR-005、FR-009）
- Q: Cookie の同意バナーを出すか？ → A: 出さない。外部送信の案内で、送信先・送る情報・目的・オプトアウトの方法を公表する（FR-009、FR-013）
- Q: サイト内に計測を止める手段を置くか？ → A: 置く。外部送信の案内に「このブラウザでは計測しない」の切り替えを置き、状態をブラウザに保存する。止めたブラウザでは計測のための読み込み・送信を行わない（FR-013、FR-014）
- Q: お気に入りの保存・削除の記録に地点を含めるか？ → A: 含めない。操作の種類だけを送り、地点・名前は送らない。人気の海域は予報画面の閲覧で把握する（FR-004、FR-005）

## 背景

Web MVP（001〜005）で、予報の表示・お気に入り地点・入力補助・フィードバック導線・ファビコンと OG 情報がそろった。しかし運営者には、実際にどれくらいの人が UMIYOMI を開き、どの画面がどれだけ見られているかを知る手段がない。フィードバック（004）は自発的に送られた声だけで、黙って使っている利用者や、途中で離れた利用者の様子は分からない。

MVP の段階では、次のことを数字で知る必要がある。

- 利用者数・閲覧数の推移（公開や告知の効果、継続して使われているか）
- トップ画面から予報画面へ進む割合、入力を受け付けなかった・予報の取得に失敗した画面の発生頻度
- スマホとデスクトップの比率、流入元（検索・共有されたリンク・直接）

この機能の目的は、MVP 後に何を作るかを判断するための利用状況を計測できるようにすることである。どの海域がよく見られているかも判断材料にするため、予報画面の緯度・経度は計測に含める。一方で、位置は生活圏を推測できる情報でもあるため、送ることを利用者に分かる形で公表し、利用者が自由に入力した文字列やお気に入りの名前のように、計測に必要のない情報は送らない。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 運営者が画面ごとの閲覧数と利用者数を確認できる (Priority: P1)

運営者が、アクセス解析サービスの管理画面で、期間ごとの利用者数・閲覧数を、画面の種類（トップ・予報・フィードバック案内・エラー）ごとに確認できる。

**Why this priority**: 計測の最小単位であり、これだけで「使われているか」「どの画面で止まっているか」が分かる。

**Independent Test**: 本番相当の設定で各画面を開き、アクセス解析サービスの管理画面（またはリアルタイム表示）に、画面の種類ごとの閲覧が記録されることを確認する。

**Acceptance Scenarios**:

1. **Given** 計測が有効な環境, **When** 利用者がトップ画面・予報画面・フィードバック案内画面・エラー画面を開く, **Then** それぞれの閲覧が、画面の種類を区別できる形で記録される
2. **Given** 計測が有効な環境, **When** 利用者が入力を受け付けなかった画面、予報の取得に失敗した画面を開く, **Then** 正常に予報が表示された画面とは区別して記録される
3. **Given** 開発・テスト環境、または計測の設定がない環境, **When** 画面を開く, **Then** 計測のための読み込みも送信も行われず、画面は従来どおり動く

---

### User Story 2 - 運営者が主要な操作の回数とよく見られる海域を確認できる (Priority: P2)

運営者が、お気に入りの保存・削除、現在地ボタン、フィードバックフォームを開く操作がどれだけ使われているか、またどの地点の予報がよく見られているかを確認できる。

**Why this priority**: 機能ごとの利用状況と人気の海域は、MVP 後に何を作るかの判断材料になる。ただし閲覧の計測（P1）だけでも最低限の価値は出る。

**Independent Test**: 計測が有効な環境で各操作を行い、アクセス解析サービスに操作の種類ごとの記録が残ること、予報画面の閲覧に地点の緯度・経度が含まれることを確認する。

**Acceptance Scenarios**:

1. **Given** 計測が有効な環境, **When** 利用者がお気に入りを保存・削除する、現在地ボタンを押す、フィードバックフォームを開く, **Then** それぞれが操作の種類を区別できる形で記録される
2. **Given** 緯度・経度を含むアドレスの予報画面, **When** 閲覧が記録される, **Then** 地点の緯度・経度が含まれ、運営者が地点ごとの閲覧数を確認できる
3. **Given** お気に入りを保存・削除する, **When** 操作が記録される, **Then** 操作の種類だけが記録され、お気に入りの地点（緯度・経度）と名前は送られない
4. **Given** 入力を受け付けなかった画面、またはフィードバック案内画面（004）が利用者の入力文字列をアドレスで受け取っている, **When** 閲覧が記録される, **Then** 利用者が入力した文字列は送られない
5. **Given** 現在地ボタンで位置を取得した, **When** 操作が記録される, **Then** 押されたこと（成功・失敗）だけが記録され、取得した位置そのものはこの操作の記録に含まれない

---

### User Story 3 - 利用者が計測について知ることができる (Priority: P2)

利用者が、UMIYOMI がどのサービスを使い、どんな情報を何のために外部へ送っているかを、画面から確認できる。

**Why this priority**: 同意バナーを出さない代わりに、外部のサービスへ送る情報（Cookie による識別子、閲覧した地点の緯度・経度を含む）を公表しておく必要がある（電気通信事業法の外部送信規律）。計測の公開前にそろえる。

**Independent Test**: どの画面からでも、外部送信の内容を説明する案内へたどり着けることを確認する。

**Acceptance Scenarios**:

1. **Given** いずれかの画面, **When** フッターを見る, **Then** 外部送信の内容を説明する案内へのリンクがある
2. **Given** 外部送信の案内, **When** 内容を読む, **Then** 送信先のサービス名（Google アナリティクス）、送る情報の種類（閲覧した画面と地点の緯度・経度、操作の種類、端末・ブラウザの情報、Cookie による識別子）、利用目的、オプトアウトの方法が分かる
3. **Given** 外部送信の案内, **When** 利用者が「このブラウザでは計測しない」に切り替える, **Then** 以降そのブラウザでは、どの画面を開いても計測のための読み込み・送信が行われない。切り替えた状態は画面を閉じても残る
4. **Given** 計測を止めたブラウザ, **When** 外部送信の案内で計測を再開に切り替える, **Then** 次に開いた画面から計測される

---

### Edge Cases

- 利用者が広告・トラッキングをブロックする拡張機能やブラウザ設定を使っている場合でも、予報の表示・お気に入り・入力補助などすべての機能は従来どおり動く
- アクセス解析サービスが落ちている・遅い場合でも、画面の表示や操作が遅くならない
- JavaScript が無効な環境でも、予報の閲覧は従来どおり動く（計測されなくてよい）
- 共有プレビューの取得元（各サービスのクローラー）や検索エンジンのアクセスで、閲覧数が大きく水増しされない
- 本番以外の環境（開発・テスト・e2e・本番イメージの起動確認）から本番の計測データへ記録が混ざらない
- 利用者が Google の提供するオプトアウトの手段、またはサイト内の切り替えで計測を止めた場合は計測されず、それでも全機能が動く
- ブラウザの保存領域（localStorage）が使えない環境では、サイト内の切り替えで計測を止めた状態を保存できない。その場合は切り替えが使えないことを案内に表示し、Google の提供するオプトアウトの手段を案内する。予報の閲覧などの機能は従来どおり動く
- 予報画面の地点を前後に移動する・お気に入りから開くなど、画面のアドレスが変わるたびに閲覧が二重・欠落なく記録される
- 回数制限（001）で予報が表示できなかった画面も、閲覧として区別して記録される

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: すべての画面（トップ・予報・フィードバック案内・エラー・外部送信の案内）の閲覧を、アクセス解析サービスに記録しなければならない
- **FR-002**: 記録される閲覧は、画面の種類（トップ・予報表示・入力不正・予報取得失敗・回数制限・フィードバック案内・その他のエラー）を区別できなければならない
- **FR-003**: アクセス解析には Google アナリティクス（GA4）を使わなければならない。広告関連の機能（広告のパーソナライズ、Google シグナル、広告サービスとのデータ連携）は使ってはならない
- **FR-004**: 画面の閲覧に加えて、次の操作を操作の種類ごとに記録しなければならない：お気に入りの保存、お気に入りの削除、現在地ボタン（成功・失敗の区別つき）、フィードバックフォームを開く。操作の記録には操作の種類（と現在地ボタンの成功・失敗）だけを含め、地点の緯度・経度、お気に入りの名前、利用者の入力文字列を含めてはならない
- **FR-005**: 予報画面の閲覧には、地点の緯度・経度（範囲内の数値として受け付けたもの）を含めてよい。緯度・経度を送るのは予報画面の閲覧の記録だけとする。利用者が自由に入力した文字列（入力不正の画面・フィードバック案内画面が受け取る入力の文字列）とお気に入りの内容（地点・名前）は、外部へ送ってはならない。送信するアドレスや記録からは、それらを含む部分を取り除かなければならない
- **FR-006**: 計測を行うかどうかと計測先の識別子は、環境ごとの設定で切り替えられなければならない。設定がない環境では計測のための読み込み・送信を一切行ってはならない。開発・テスト・e2e・本番イメージの起動確認は、既定で計測しない
- **FR-007**: 計測のための読み込みは、画面の表示・操作を待たせてはならない。計測サービスが使えない・ブロックされている場合も、すべての機能が従来どおり動かなければならない
- **FR-008**: 予報の閲覧・お気に入り・入力補助（001〜003）は、JavaScript が無効または計測がブロックされた状態でも従来どおり動かなければならない
- **FR-009**: すべての画面から、外部送信の内容（送信先のサービス名、送る情報の種類、利用目的、オプトアウトの方法）を説明する案内へたどり着けなければならない。送る情報には、閲覧した地点の緯度・経度と Cookie による識別子を含むことを明記しなければならない
- **FR-010**: 外部送信の案内には、UMIYOMI が航海の安全を保証しないことを損なう文言（「安全です」等の断定）を含めてはならない
- **FR-011**: 計測の結果をサーバー側に保存してはならない。サーバー側に新しいデータの保存を作らない。localStorage のお気に入りの形式（002）も変えない（計測を止めた状態は、お気に入りとは別の項目として保存する）
- **FR-012**: 外部の海況 API の呼び出し回数・予報の回数制限（001）に、計測が影響してはならない
- **FR-013**: Cookie の同意バナーは表示しない。計測を拒否したい利用者には、外部送信の案内で、サイト内の切り替え（FR-014）と Google の提供するオプトアウトの手段の両方を示す
- **FR-014**: 外部送信の案内に、このブラウザで計測するかどうかの切り替えを置かなければならない。既定は「計測する」とする。「計測しない」にしたブラウザでは、どの画面でも計測のための読み込み・送信を行ってはならない。状態はブラウザに保存し、画面を閉じても残らなければならない。切り替えは、計測の設定がない環境（FR-006）では表示しなくてよい

### Key Entities

- **閲覧の記録**: 画面の種類・日時・端末の種類・流入元・（予報画面では）地点の緯度・経度など、アクセス解析サービスに送られる 1 回分の閲覧。利用者が自由に入力した文字列は含まない
- **操作の記録**: 操作の種類（お気に入りの保存・削除、現在地ボタンの成功・失敗、フィードバックフォームを開く）。地点の緯度・経度、お気に入りの名前、現在地の位置そのものは含まない
- **計測の設定**: 環境ごとに、計測するかどうかと計測先の識別子を決める値。未設定なら計測しない
- **計測を止めた状態**: 利用者がブラウザごとに選ぶ「計測しない」の状態。そのブラウザだけに保存され、サーバーには送らない
- **外部送信の案内**: 送信先・送る情報・目的・オプトアウト方法を利用者に示す固定の説明

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 本番環境で各画面を 1 回ずつ開くと、アクセス解析サービスの管理画面で画面の種類ごとに閲覧が確認できる
- **SC-002**: アクセス解析サービスへ送られる内容に、利用者が自由に入力した文字列・お気に入りの内容（地点・名前）が含まれるケースが 0 件である。また、操作の記録に緯度・経度が含まれるケースが 0 件である
- **SC-003**: 計測の設定がない環境で、外部の計測サービスへの通信が 0 件である
- **SC-004**: 計測サービスへの通信を遮断した状態で、予報の表示・お気に入りの保存・入力補助・フィードバック導線の既存の自動テストがすべて通る
- **SC-005**: 計測を導入しても、トップ画面・予報画面の初回表示にかかる時間が体感で悪化しない（表示の完了を計測の読み込みが待たせない）
- **SC-006**: すべての画面から、2 回以内の操作で外部送信の案内にたどり着ける
- **SC-007**: 本番環境で 4 種類の操作（お気に入りの保存・削除、現在地ボタン、フィードバックフォームを開く）を行うと、管理画面で操作の種類ごとに記録が確認できる
- **SC-008**: 「計測しない」に切り替えたブラウザで各画面を開いたとき、計測サービスへの通信が 0 件である

## Assumptions

- 計測データの閲覧・分析は、アクセス解析サービスの管理画面で行う。UMIYOMI 内に集計画面やダッシュボードは作らない
- Google アナリティクスのアカウント・プロパティの作成、計測 ID の発行、データ保持期間などの管理画面側の設定は、運営者が行う。本番への設定の反映方法は既存の環境変数の手順（004 の `FEEDBACK_FORM_URL` と同様）に合わせる
- 日本の外部送信規律では、アクセス解析のための送信は公表で足りる前提とし、同意の取得は行わない。EU など海外の利用者向けの同意管理は対象外とする
- 外部送信の案内は、UMIYOMI 内の固定の 1 画面とする。プライバシーポリシー全体の整備や利用規約は、この機能の対象外とする
- 広告の配信・広告目的のデータ連携・他サービスとのデータ共有は行わない
- 多言語対応は行わない。日本語のみとする
- A/B テスト、ヒートマップ、セッション録画などの高度な分析は対象外とする
