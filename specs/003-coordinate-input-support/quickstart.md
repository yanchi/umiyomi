# Quickstart: 緯度・経度の入力サポート

**Feature**: 003-coordinate-input-support | **Date**: 2026-10-05

コマンドはリポジトリ直下で実行する。新しいパッケージ・拡張は追加しないので、イメージの再ビルドは不要。

## 自動テスト

```sh
docker compose up -d
docker compose exec php vendor/bin/phpunit --filter CoordinateNotationParserTest   # 表記の読み取り（SC-002 の表を含む）
docker compose exec php vendor/bin/phpunit --filter CoordinateQueryParserTest      # 2 欄の組み合わせ・順序・正規形
docker compose exec php composer test:js                                           # 現在地の取得・2 桁の書式（node --test）
docker compose exec php composer check                                             # すべて（作業完了前に必ず通す）
```

## ブラウザでの確認

http://localhost:8000 を開く。Geolocation は `localhost` では HTTPS でなくても動く。

### US1：「緯度, 経度」の貼り付け

| 入力（緯度欄 / 経度欄） | 期待 |
|---|---|
| `27.75, 129.05` / 空 | URL が `/forecast?lat=27.75&lon=129.05` になり、入力欄に `27.75` と `129.05` が分かれて入る |
| `27.75 129.05`、`27.75、129.05`、`(27.75, 129.05)`、`２７．７５，１２９．０５` / 空 | 同上 |
| `27.75000° N, 129.05000° E` / 空（iPhone の「マップ」の形） | 同上 |
| 予報画面で緯度欄を `35.10, 139.20` に書き換えて送信（経度欄は `129.05` のまま） | 緯度 35.10・経度 139.20 の予報。「経度欄に入っていた値は使っていません」が出る |
| `129.05, 27.75` / 空 | 予報は出ず、「緯度と経度の順序が逆になっている可能性があります」 |
| `35.00, 45.00` / 空 | 入れ替えずに緯度 35.00・経度 45.00 の予報。地点の表示で確認できる |
| 両方の欄に `27.75, 129.05` | 両方の欄に「どちらか一方の欄だけに入力してください」 |

### US2：度分・度分秒

| 入力（緯度欄 / 経度欄） | 期待（URL の lat / lon） |
|---|---|
| `27°45.0'N` / `129°03.0'E` | 27.75 / 129.05 |
| `27°45'00"N` / `129°03'00"E` | 27.75 / 129.05 |
| `N27°45.0' E129°03.0'` / 空 | 27.75 / 129.05 |
| `N27-45.0` / `E129-03.0` | 27.75 / 129.05 |
| `北緯27度45分` / `東経129度3分` | 27.75 / 129.05 |
| `27°45.3'` / `129.05`（丸めの境目） | 27.76 / 129.05 |
| `S27°45.3'` / `W129°03.0'` | -27.76 / -129.05 |
| `27.755` / `129.05` | 27.76 / 129.05 |
| `27°75'N` / `129.05` | 予報は出ず「分・秒は 0 以上 60 未満で入力してください」 |
| `-27°45'N` / `129.05` | 予報は出ず「マイナス記号と方角の文字の両方があります」 |
| `27°45'E` / `129.05` | 予報は出ず「緯度には N（北緯）か S（南緯）を付けてください」 |

**スマホ（iPhone）で必ず確認する**：入力欄をタップすると文字のキーボードが出る（数字だけのキーボードにならない）。
`27°45'00"N` を手入力し、スマート句読点で `’` `”` に変わっても受け付けられる。自動大文字化・自動修正で入力が書き換わらない。

### US3：受け付けられない入力

| 入力 | 期待 |
|---|---|
| `北緯二十七度` | 「緯度を読み取れませんでした。入力例：…」。入力した文字列が欄に残る |
| `27.75, 129.05, 10` | 「緯度と経度の 2 つだけを入力してください」 |
| `27 45.0 129 03.0` | 「度と分の記号を付けてください」 |
| `N27 45.0` | 「両方に方角の文字を付けるか、両方とも付けずに」 |
| `https://maps.app.goo.gl/xxxx` | 「リンクからは地点を読み取れません」 |
| 101 文字の文字列 | 「入力が長すぎます」 |

### US4：現在地

1. トップ画面に「現在地を入力」と、陸地・港の内側についての案内が出る
2. 押す →「現在地を取得しています…」、ボタンが押せなくなる → 許可すると入力欄に 2 桁の値が入る。予報はまだ出ない
3. 送信 → その地点の予報画面
4. 予報画面で「現在地を入力」→ 入力欄が変わり、「入力欄の地点の予報はまだ表示していません」が出る → 値を元に戻すと消える → 送信すると切り替わる
5. 予報画面で入力欄を手で書き換えたときも 4. の案内が出る
6. 位置情報を拒否 →「位置情報の利用が許可されなかったため…」、入力欄は変わらない
7. DevTools の Sensors で位置を「Location unavailable」にする、または通信を遮断する → 15 秒以内に「現在地を取得できませんでした」
8. 取得中に入力欄を書き換える → 結果で上書きされず「入力欄が変更されたため…」
9. DevTools で JavaScript を無効にする →「現在地を入力」が表示されない。緯度・経度の入力と予報の表示はできる
10. 予報画面の保存パネルに「保存される地点：北緯 … / 東経 …（表示中の地点）」が出る。入力欄を書き換えても変わらない

### 360px 幅

DevTools のデバイスモードで幅 360px にし、トップ画面・予報画面・エラー表示・現在地のメッセージでページ全体が横にはみ出さないこと（FR-013）。
