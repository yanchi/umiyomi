# Feature Specification: ファビコンと OG 情報

**Feature Branch**: `005-favicon-og-meta`
**Created**: 2026-10-05
**Status**: Draft
**Input**: User description: "ファビコンの作成とog情報を設定したい"

## Clarifications

### Session 2026-10-05

- Q: どの画面を検索エンジンに登録してよいか？ → A: トップ画面だけ登録を許可する。予報・フィードバック案内・エラー画面は登録しない。共有プレビューは全画面で機能させる（FR-011）

## 背景

現在の UMIYOMI には専用のアイコン（ファビコン）がなく、ブラウザのタブ・ブックマーク・ホーム画面では既定の汎用アイコンが表示される。また、ページの説明や共有用の情報（OG 情報）が設定されていないため、URL を LINE・X・Slack などに貼ったときに、サービス名・説明・画像のないそっけない表示になる。

出航前に仲間へ「ここの予報を見て」と URL を送る使い方は自然に起こる。そのときにサービスの名前と目的が伝わり、タブやブックマークでも UMIYOMI だと一目で分かるようにするのが、この機能の目的である。

なお、アプリ内に共有ボタンを置く機能（共有・SNS）は MVP の対象外であり、この機能でも作らない。利用者が自分で URL を貼ったときの見え方だけを整える。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - タブ・ブックマークで UMIYOMI だと分かる (Priority: P1)

利用者が複数のタブを開いている、またはブックマーク・ホーム画面に UMIYOMI を保存しているときに、専用のアイコンで UMIYOMI を見分けられる。

**Why this priority**: 出航前は天気・潮・UMIYOMI など複数のページを行き来する。タブを探す手間を減らす、最も日常的な価値。

**Independent Test**: どの画面を開いても、ブラウザのタブに UMIYOMI 専用のアイコンが表示されることを確認する。ブックマーク追加・ホーム画面追加でも同じアイコンが使われることを確認する。

**Acceptance Scenarios**:

1. **Given** 利用者がトップ画面・予報画面・フィードバック案内画面・エラー画面のいずれかを開いている, **When** ブラウザのタブを見る, **Then** 既定の汎用アイコンではなく UMIYOMI 専用のアイコンが表示される
2. **Given** 利用者がスマホでホーム画面に UMIYOMI を追加する, **When** ホーム画面を見る, **Then** 専用アイコンが崩れず、切り取られず、他のアプリアイコンと並んでも判別できる大きさで表示される
3. **Given** ブラウザがライトテーマ・ダークテーマのどちらでも, **When** タブを見る, **Then** アイコンが背景に埋もれず判別できる

---

### User Story 2 - URL を貼ったときにサービスの内容が伝わる (Priority: P1)

利用者が UMIYOMI の URL をチャットアプリや SNS に貼ったとき、サービス名・短い説明・イメージ画像がプレビューとして表示され、受け取った人が何のページか理解してから開ける。

**Why this priority**: 仲間への URL 共有は出航前の自然な使い方であり、プレビューがないと不審なリンクに見えて開かれにくい。

**Independent Test**: 共有プレビューを確認できる手段（各サービスのプレビュー確認ツールや、ページに設定された共有用情報の確認）で、トップ画面の URL がタイトル・説明・画像つきで解釈されることを確認する。

**Acceptance Scenarios**:

1. **Given** トップ画面の URL, **When** チャットアプリや SNS に貼る, **Then** サービス名「UMIYOMI」、サービスの目的が分かる短い説明、イメージ画像がプレビューに表示される
2. **Given** 緯度・経度つきの予報画面の URL, **When** 貼る, **Then** サービス名と説明つきのプレビューが表示され、画像も表示される
3. **Given** プレビューに表示される説明文, **When** 内容を読む, **Then** 「安全です」「出航できます」のような断定を含まず、予報を確認するサービスであることだけが伝わる

---

### User Story 3 - 画面ごとに適切なタイトル・説明が付く (Priority: P2)

利用者がブラウザの履歴・共有プレビュー・検索結果（トップ画面）で UMIYOMI のページを見たとき、ページの内容に合ったタイトルと説明が表示される。

**Why this priority**: 全ページが同じ文言だと見分けが付かない。ただし P1 の 2 つが満たされていれば最低限の価値は出る。

**Independent Test**: 各画面のタイトルと説明が、その画面の内容に合っていることを確認する。

**Acceptance Scenarios**:

1. **Given** 予報画面, **When** 共有用情報を確認する, **Then** タイトルに地点の座標が含まれ、トップ画面とは区別できる
2. **Given** エラー画面・フィードバック案内画面, **When** 共有用情報を確認する, **Then** 共有されても意味が通るタイトルが付いている

---

### Edge Cases

- 利用者が入力した文字列（緯度・経度）がタイトルや説明にそのまま入る場合、特殊な文字や長い文字列でも共有用情報が壊れず、改ざんされた内容が表示されない
- 予報の取得に失敗した URL・入力が不正な URL を貼ったとき、プレビューに誤解を招く予報の数値が出ない
- 共有用の画像が表示できないサービスでは、タイトルと説明だけで成立する
- アイコンが古いまま表示される（ブラウザのキャッシュ）場合でも、差し替えたときに最終的に新しいものへ切り替わる
- 共有プレビューの取得元（各サービスのクローラー）がアクセスしても、回数制限などで失敗しない
- 予報の最終更新日時やリアルタイムの数値は、プレビューに載せない（キャッシュされて古い値が長く残るため）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: すべての画面（トップ・予報・フィードバック案内・エラー）で、UMIYOMI 専用のアイコンがブラウザのタブとブックマークに表示されなければならない
- **FR-002**: アイコンは、一般的なブラウザ（デスクトップ・スマホ）とホーム画面追加で、それぞれの用途に合う大きさ・形式で提供されなければならない（小さいタブ表示でも判別でき、ホーム画面では余白を含めて切り取られない）
- **FR-003**: アイコンのデザインは、UMIYOMI（海・波・予報）を連想できるもので、小さいサイズでも輪郭が判別できなければならない。ライトテーマ・ダークテーマのどちらの背景でも見分けられなければならない
- **FR-004**: すべての画面に、サービス名・短い説明・イメージ画像を含む共有用情報（OG 情報）が設定されなければならない
- **FR-005**: 共有用のイメージ画像は、主要なチャットアプリ・SNS で切り取られず表示される縦横比・大きさでなければならない。画像には代替テキストが付かなければならない
- **FR-006**: 共有用情報の画像の参照先は、外部のサービスから取得できる完全なアドレスでなければならない
- **FR-007**: 画面ごとに、内容に合ったタイトルと説明が設定されなければならない。予報画面のタイトルには地点の座標を含めてよいが、予報の数値や最終更新日時は含めない
- **FR-008**: 共有用情報の文言に、「安全です」「出航できます」「問題ありません」のような断定を含めてはならない。必要な場合は、予報を確認するサービスであることと、公式な警報・注意報の確認を併せて案内する旨にとどめる
- **FR-009**: 利用者が入力した文字列を共有用情報に含める場合は、決まった形の値（範囲内の数値）だけを使い、それ以外は含めない。長さや特殊文字でページが壊れてはならない
- **FR-010**: 入力不正・予報取得失敗の画面は、共有用情報にエラーの詳細や利用者の入力文字列を含めない
- **FR-011**: トップ画面だけ検索エンジンへの登録を許可し、予報・フィードバック案内・エラー画面は登録されない設定にしなければならない。いずれの画面でも共有プレビューは機能しなければならない
- **FR-012**: アイコン・共有用画像の取得は、予報の回数制限の対象にしてはならない。また、予報の取得（外部 API の呼び出し）を発生させてはならない
- **FR-013**: アイコンと共有用画像は、画面の表示・操作を遅くしてはならない（画面の表示に必須の取得を増やさない）
- **FR-014**: サーバー側に新しいデータの保存を作ってはならない。localStorage の形式（002）も変えない

### Key Entities

- **サイトアイコン**: ブラウザのタブ・ブックマーク・ホーム画面で使われる UMIYOMI のマーク。用途ごとに複数のサイズ・形式がある
- **共有用情報（OG 情報）**: 画面ごとのタイトル・説明・画像・サービス名の組。URL が貼られたときのプレビュー表示に使われる
- **共有用画像**: プレビューに表示される、サービス名とイメージを含む 1 枚の画像（全画面で共通）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: すべての画面（トップ・予報・フィードバック案内・エラー）で、既定の汎用アイコンが表示される画面が 0 件である
- **SC-002**: 主要なチャットアプリ・SNS 各社のプレビュー確認で、トップ画面と予報画面の URL がタイトル・説明・画像つきで表示される
- **SC-003**: タブ表示の最小サイズ（16px 四方）とホーム画面表示で、アイコンが判別でき、切り取られないことを目視で確認できる
- **SC-004**: 共有用情報の文言に、安全性を断定する語句が 0 件含まれる
- **SC-005**: 新しい画像・アイコンを追加しても、トップ画面・予報画面の初回表示にかかる時間が悪化しない（表示に必須の取得が増えない）
- **SC-006**: 自動テストで、全画面にアイコンと共有用情報が設定されていること、入力不正な値が共有用情報に入らないことを確認できる

## Assumptions

- 共有用の画像は、サービスのロゴ・名前・キャッチコピーだけを含む固定の 1 枚とする。地点や予報の数値に応じて生成する動的な画像は作らない
- アイコンと共有用画像のデザインは、この機能のなかで新しく作る。既存のロゴ素材は無い前提で、波をモチーフにしたシンプルなマークとする。デザインの最終的な確認は人間が行う
- ページの説明文はサービスの目的を短く伝える固定の文言とし、予報画面だけタイトルに座標を含める。文言の最終案は計画時に確認する
- 共有用情報の画像の参照先には、公開 URL の基準となるアドレスが必要になる。本番で設定済みのものを使い、未設定の環境（開発・テスト）では相対でも壊れない扱いとする。具体的な方法は計画で決める
- MVP の対象外である共有ボタン・SNS 連携・Push 通知・PWA（オフライン対応を含む）は作らない。ホーム画面追加時のアイコンだけ整える
- 多言語対応は行わない。日本語のみとする
- 実際のサービス名の商標・既存の他社ロゴと紛らわしいデザインは避ける
