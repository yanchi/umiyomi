# Feature Specification: 検索エンジン対策（SEO）

**Feature Branch**: `007-seo-optimization`
**Created**: 2026-10-05
**Status**: Draft
**Input**: User description: "SEO対策したい"

## Clarifications

### Session 2026-10-05

- Q: 本番の登録拒否の指示を外す「公開の操作」をこの機能に含めるか？ → A: 含める。リポジトリの Web サーバー設定と本番確認の手順から登録拒否の指示を外し、マージ・デプロイ後に検索エンジンへの登録が始まる状態にする。本番サーバー上の設定の反映は運営者が手順書に従って行う（FR-002、FR-013、FR-016）
- Q: 検索エンジンの管理ツールでのサイトの所有確認の方法は？ → A: ドメインの DNS（TXT レコード）で行う。アプリの画面・設定・公開ファイルには確認用の情報を追加しない（FR-013、FR-017）
- Q: トップ画面に例の地点の予報へのリンクを置くか？ → A: 置かない。使い方の文章の中で入力例の値を示すだけにする。特定の海域を勧める表現も避ける（FR-007）

## 背景

Web MVP（001〜006）で、予報の表示・お気に入り地点・入力補助・フィードバック導線・ファビコンと共有プレビュー（OG）・アクセス解析がそろった。005 で「トップ画面だけ検索エンジンへの登録を許可し、予報・フィードバック案内・エラー画面は登録しない」と決め、アプリ側の設定は済んでいる。

しかし現状では、検索から UMIYOMI にたどり着く人はいない。

- 本番の Web サーバーが公開前の措置として全画面に「登録しない」指示を付けており、トップ画面も検索エンジンに登録されない
- 検索エンジンに対して、どのページを登録してほしいか・どのアドレスが正規かを伝える手段がない
- トップ画面の本文は入力欄が中心で、「何ができるサービスか」「どんな数値が見られるか」を検索エンジンや初めて来た人が読み取れる文章が少ない

この機能の目的は、出航前に海況を調べようとしている人（例：「風 波 うねり 予報」「出航前 海況」などで検索する人）が、検索結果から UMIYOMI のトップ画面を見つけ、内容を理解したうえで使い始められるようにすることである。あわせて、運営者が登録状況を確認できるようにする。

一方で、予報画面は緯度・経度の組み合わせごとに無数のアドレスがあり、中身は数値の一覧だけで、時間がたつと内容が古くなる。これらが検索結果に大量に載ると、古い予報が検索結果に残って誤解を招くおそれがあり、サイト全体の評価も下がりうる。そのため、登録の対象は意図して選んだページに限る。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 検索した人が検索結果から UMIYOMI を見つけて使い始められる (Priority: P1)

出航前に海況を調べようとしている人が、検索エンジンで関連する語句を検索し、検索結果に UMIYOMI のトップ画面が、サービス内容の分かるタイトルと説明つきで表示される。クリックすると、トップ画面で何ができるかがすぐ分かり、そのまま緯度・経度を入力して予報を見られる。

**Why this priority**: 検索からの新規利用者の獲得そのものであり、この機能の目的に直結する。トップ画面が登録されなければ他の対策は意味を持たない。

**Independent Test**: 本番環境でトップ画面が「登録してよい」状態で返り、検索エンジンの管理ツールの URL 検査で「登録可能」と判定されることを確認する。トップ画面の本文だけを読んで、サービスの内容・表示される数値の種類・使い方が分かることを確認する。

**Acceptance Scenarios**:

1. **Given** 本番環境, **When** 検索エンジンのクローラーがトップ画面を取得する, **Then** 登録を拒否する指示（ページ内・応答ヘッダーのいずれも）が含まれていない
2. **Given** 本番環境, **When** クローラーが予報・フィードバック案内・エラー画面を取得する, **Then** 従来どおり「登録しない」指示が含まれている
3. **Given** 初めて来た人, **When** トップ画面を開く, **Then** 入力欄の近くに、指定した地点の風・波・うねりを時間別に確認できるサービスであること、表示される数値の種類（風速・風向・波高・波向・波周期・うねり）、使い方の手順、航海の安全を保証しないことと公式の警報・注意報の確認の案内が、文章として表示されている
4. **Given** トップ画面, **When** 文章を追加したあと, **Then** スマホ幅でも入力欄が最初の画面内に収まり、予報を見るまでの操作の手間は従来から増えていない

---

### User Story 2 - 検索エンジンが登録すべきページと正規のアドレスを正しく理解できる (Priority: P2)

検索エンジンのクローラーが UMIYOMI を巡回したとき、登録してほしいページの一覧と、各ページの正規のアドレスを受け取れる。同じ内容のトップ画面が、余計な付加情報つきのアドレス（例：広告やアクセス解析用のパラメーターつき）で別のページとして扱われない。

**Why this priority**: 登録の速さと正確さを高めるが、トップ画面が登録可能になること（P1）が前提で、それだけでも最低限の効果は出る。

**Independent Test**: サイトのクローラー向けの案内とページ一覧を取得し、登録対象のページだけが正規のアドレスで列挙されていることを確認する。パラメーターつきのアドレスでトップ画面を開き、正規のアドレスがパラメーターなしのトップ画面を指していることを確認する。

**Acceptance Scenarios**:

1. **Given** 本番環境, **When** クローラーがサイトの決まった場所にあるクローラー向けの案内を取得する, **Then** 登録対象ページの一覧の場所が示され、トップ画面の取得は妨げられていない
2. **Given** 本番環境, **When** クローラーが登録対象ページの一覧を取得する, **Then** 登録対象のページだけが、本番の正規アドレス（https・公開ドメイン）で列挙されている
3. **Given** 任意のパラメーターがついたトップ画面のアドレス, **When** 開く, **Then** 画面は従来どおり表示され、正規のアドレスとしてパラメーターなしのトップ画面のアドレスが示されている
4. **Given** 開発・テスト環境, **When** 案内や一覧を取得する, **Then** その環境のアドレスが本番の正規アドレスとして混ざることはない（本番以外の環境が検索エンジンに登録されない）

---

### User Story 3 - 検索結果でサービスの種類が伝わる (Priority: P3)

検索エンジンが、UMIYOMI を「海況予報を確認する無料の Web サービス」として機械的に理解できる情報を受け取り、検索結果の表示（サイト名など）に反映できる。

**Why this priority**: 検索結果での見え方を改善する補助的な対策。なくても登録・表示はされる。

**Independent Test**: トップ画面に含まれる構造化された情報を、検索エンジンが提供する検証ツールで検証し、エラーがないことを確認する。

**Acceptance Scenarios**:

1. **Given** トップ画面, **When** 検証ツールで検査する, **Then** サイト名・サービスの説明・正規のアドレスを表す構造化された情報が、エラーなく読み取れる
2. **Given** 構造化された情報, **When** 内容を確認する, **Then** 画面に表示されている内容と矛盾せず、安全を保証するような表現や、存在しない評価・料金などの情報を含まない

---

### User Story 4 - 運営者が検索での登録・表示状況を確認できる (Priority: P3)

運営者が、検索エンジンの管理ツールで、UMIYOMI がどのように登録・表示されているか（登録されたページ、表示回数、クリック数、検索された語句）を確認できる。

**Why this priority**: 効果測定のための運用面の準備。アプリの機能ではなく手順の整備が中心。

**Independent Test**: 手順書に従って管理ツールにサイトを登録し、所有者の確認とページ一覧の送信が完了することを確認する。

**Acceptance Scenarios**:

1. **Given** 運営者, **When** 手順書に従う, **Then** 管理ツールでのサイトの所有確認、ページ一覧の送信、登録状況の確認ができる
2. **Given** この機能のマージ後, **When** 運営者が手順書に従って本番サーバー上の Web サーバー設定を反映する, **Then** 反映の前後で何を確認すればよいか（トップだけが登録対象で、他の画面は登録されないこと）が分かり、そのとおりの状態になる

### Edge Cases

- 予報画面のアドレスが外部（SNS・ブログなど）からリンクされても、予報画面は登録されない。リンクをたどったクローラーが予報画面を取得しても、外部の海況 API の呼び出し回数が急増しない（既存のキャッシュと回数制限の範囲内で処理される）
- クローラー向けの案内で予報画面の取得を禁止すると、クローラーが「登録しない」指示を読めなくなり、かえってアドレスだけが検索結果に載ることがあるため、予報画面の取得は禁止しない
- 存在しないアドレス（404）やエラー画面は、従来どおり「登録しない」状態で正しいエラーの状態を返し、登録対象ページの一覧にも含まれない
- 外部送信についての案内画面は登録しない（運営上の案内であり、検索からの入口にする必要がない）
- トップ画面に追加する文章が、お気に入り地点の一覧や入力欄の操作を妨げない。localStorage が使えない環境や JavaScript が無効な環境でも、文章は表示される
- 本番サーバー上の Web サーバー設定の反映（運営者の手作業）が、アプリのデプロイより前後しても問題が起きない。反映前は従来どおり全画面が登録されず、反映後はトップだけが登録対象になる
- Web サーバーの登録拒否の指示を外したあとも、アプリが返さない応答（Web サーバーが直接返すエラーなど）が検索結果に載る状態にならない

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 検索エンジンへの登録対象はトップ画面だけとし、予報・フィードバック案内・外部送信についての案内・エラー画面は引き続き登録しない設定にしなければならない（005 の FR-011 を維持する）
- **FR-002**: 本番環境で、トップ画面の取得時に、ページ内・応答ヘッダーのいずれにも登録を拒否する指示が含まれない状態にしなければならない。この機能は公開の操作を含み、リポジトリで管理する Web サーバー設定から、全画面に付けている登録拒否の指示を外す
- **FR-003**: サイトの決まった場所に、クローラー向けの案内を置かなければならない。案内は登録対象ページの一覧の場所を示し、どの画面の取得も禁止しない
- **FR-004**: 登録対象ページの一覧を提供しなければならない。一覧には登録対象のページ（FR-001）だけを、本番の正規アドレスで含める
- **FR-005**: すべての画面で、正規のアドレスを示さなければならない。トップ画面の正規のアドレスは、パラメーターを含まないトップ画面のアドレスとする。登録しない画面に正規のアドレスを示すかどうかは計画で決めてよいが、予報画面の正規のアドレスとして別の地点やトップ画面を指してはならない
- **FR-006**: 正規のアドレスと登録対象ページの一覧のアドレスは、本番の公開アドレス（https・公開ドメイン）を基準に組み立てなければならない。アクセスに使われたホスト名や、開発・テスト環境のアドレスをそのまま使ってはならない
- **FR-007**: トップ画面に、サービスの内容を説明する文章を表示しなければならない。少なくとも、(a) 指定した緯度・経度の風・波・うねりを時間別に確認できること、(b) 表示される数値の種類（風速・風向・波高・波向・波周期・うねり）、(c) 入力例の値を含む使い方の手順（例の値は文章として示し、予報画面へのリンクにはしない）、(d) 航海の安全を保証しないことと、気象庁などの公式な警報・注意報の確認の案内、を含める
- **FR-007a**: トップ画面に追加する文章には、予報画面へのリンクや、特定の海域・地点を勧める表現を含めてはならない
- **FR-008**: トップ画面の文章は、入力欄より後ろ（または入力欄の操作を妨げない位置）に置き、スマホ幅でも入力欄が最初の画面内に収まるようにしなければならない
- **FR-009**: トップ画面の見出しは、ページの主題（サービス名とできること）が分かる階層構造にしなければならない。ページの最上位の見出しは 1 つとする
- **FR-010**: トップ画面のタイトルと説明文は、検索結果に表示されたときに、サービスの内容（出航前に風・波・うねりの予報を確認できること）が分かる内容にしなければならない。説明文は検索結果で途中で切れにくい長さ（全角でおおむね 120 文字以内）とする
- **FR-011**: トップ画面に、サイト名・サービスの説明・正規のアドレスを表す構造化された情報を含めなければならない。内容は画面の表示と矛盾してはならず、評価・料金・安全性など画面にない情報を含めてはならない
- **FR-012**: 追加・変更するすべての文言（画面の文章、タイトル、説明文、構造化された情報）は、「安全です」「出航できます」「問題ありません」のような断定を含んではならない
- **FR-013**: 運営者向けの手順書に、本番サーバー上の Web サーバー設定から登録拒否の指示を外す手順、反映の前後で確認すること（トップだけが登録対象で、他の画面は登録されないこと）、検索エンジンの管理ツールでのサイトの所有確認（DNS の TXT レコードによる）・ページ一覧の送信・登録状況の確認、を記載しなければならない。「公開するまで」を前提にした既存の記述は、公開後の状態に合わせて改める
- **FR-014**: この機能は、利用者のデータを新たに保存・送信してはならない。localStorage の形式（002・006）も変えない
- **FR-015**: 予報画面がクローラーから取得されても、外部の海況 API への呼び出しは既存のキャッシュと回数制限の範囲で処理されなければならない（クローラー専用の扱いは追加しない）
- **FR-016**: 本番用の構成を確かめる自動の確認（全 PR で実行されるもの）は、「全画面に登録拒否の指示が付いていること」の確認をやめ、代わりに「トップ画面に登録拒否の指示がなく、予報・フィードバック案内・外部送信についての案内・エラー画面には付いていること」と「クローラー向けの案内と登録対象ページの一覧が取得できること」を確認しなければならない
- **FR-017**: 管理ツールでのサイトの所有確認のために、アプリの画面・設定・公開ファイルへ確認用の情報を追加してはならない（確認は DNS で行う）

### Key Entities

- **登録対象ページ**: 検索エンジンに登録してよいページ。現時点ではトップ画面だけ。正規のアドレスを持つ
- **正規のアドレス**: あるページの代表となるアドレス。本番の公開アドレスを基準にし、パラメーターを含まない
- **登録対象ページの一覧**: 登録対象ページの正規のアドレスを列挙したもの。クローラー向けの案内から場所が示される

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 公開の操作のあと、検索エンジンの管理ツールの URL 検査で、トップ画面が「登録可能」と判定され、予報・フィードバック案内・外部送信についての案内・エラー画面は「登録しない指示により除外」と判定される
- **SC-002**: 公開の操作とページ一覧の送信から 4 週間以内に、トップ画面が検索エンジンに登録され、サービス名「UMIYOMI」での検索結果に表示される
- **SC-003**: 管理ツールで登録されているページのうち、予報画面のアドレスが 0 件である
- **SC-004**: 構造化された情報の検証ツールで、トップ画面のエラーが 0 件である
- **SC-005**: 初めて見る人 5 人に、入力をする前のトップ画面だけを見せたとき、5 人全員が「どんな数値が見られるサービスか」を答えられる
- **SC-006**: スマホ幅（幅 375px 相当）でトップ画面を開いたとき、スクロールせずに緯度・経度の入力欄と「予報を表示」ボタンが見える
- **SC-007**: アクセス解析（006）で、公開の操作から 3 か月以内に、流入元が自然検索の訪問が記録される

## Assumptions

- 検索エンジンは、日本で利用者の多い Google を主な対象とする。管理ツールは Google Search Console を想定する。他の検索エンジンも同じ標準的な指示（ページ内の登録指示、クローラー向けの案内、ページ一覧）で対応できる範囲で扱う
- 管理ツールでのサイトの所有確認は、運営者がドメインの DNS（TXT レコード）で行う（FR-017）。運営者は `isl-mentor.com` の DNS を変更できる
- 本番の公開アドレスは `https://umiyomi.isl-mentor.com` で、アプリはすでに公開アドレスを設定として持っている（005 の共有プレビューで使用）
- 地域別・港別などの入口ページ（例：「〇〇港の波予報」）は作らない。地点を選んで見せる機能は MVP の範囲外（地図指定と同様）であり、検索の入口はトップ画面だけとする
- 予報画面を登録しない方針（005）は変えない。予報は時間で古くなり、地点ごとに無数のアドレスがあるため
- 被リンク獲得・広告・SNS での告知など、サイトの外で行う施策はこの機能に含めない
- 表示速度については、現状のトップ画面が軽量であることから、新たな高速化の施策は前提にしない。文章の追加で表示が目に見えて遅くならないことだけを求める
- 英語など他の言語のページは作らない（日本語のみ）
- 新しいパッケージ・外部サービスの読み込みは追加しない
