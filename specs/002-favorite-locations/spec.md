# Feature Specification: お気に入り地点の保存と呼び出し

**Feature Branch**: `002-favorite-locations`
**Created**: 2026-10-05
**Status**: Draft
**Input**: User description: "お気に入り保存"

## Clarifications

### Session 2026-10-05

- Q: お気に入り一覧をどの画面に表示するか？ → A: トップ画面と予報画面の両方に表示する。予報画面の一覧は地点を選んで開くだけで、名前変更・削除はトップ画面の一覧で行う
- Q: お気に入り一覧の並び順は？ → A: 新しく保存したものが上。利用者による並べ替えは持たない
- Q: 予報画面のどこにお気に入り一覧を置くか？ → A: 入力欄の近く（予報一覧より上）に、最初は折りたたんだ状態で置き、利用者が開くと一覧が表示される
- Q: トップ画面でお気に入り一覧と入力欄のどちらを上にするか？ → A: 入力欄が上、そのすぐ下にお気に入り一覧
- Q: 異なる地点に同じ名前を付けられるか？ → A: 付けられる。名前の重複では保存・名前変更を止めない（一覧には緯度・経度も表示されるため区別できる）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 表示中の地点をお気に入りに保存し、一覧から開き直す (Priority: P1)

よく行くポイントがいくつか決まっている利用者が、予報画面で表示中の地点をお気に入りに保存する。保存するときに「〇〇港沖」のような分かりやすい名前を付けられる。次に UMIYOMI を開いたとき、トップ画面のお気に入り一覧から名前を選ぶだけで、緯度・経度を入力し直さずにその地点の予報を表示できる。

**Why this priority**: Web MVP の完成条件「地点をお気に入り保存」そのもの。出航のたびに緯度・経度を調べて入力し直す手間をなくし、前日の夜と当日の朝に同じ地点を確認する使い方を簡単にする。

**Independent Test**: 緯度 27.75・経度 129.05 の予報画面で名前「テスト沖」を付けて保存し、ブラウザを閉じて開き直したトップ画面のお気に入り一覧に「テスト沖」が表示され、それを選ぶとその地点の予報が表示されることを確認すればテストできる。

**Acceptance Scenarios**:

1. **Given** 緯度 27.75・経度 129.05 の予報を表示している、**When** 名前「テスト沖」を付けてお気に入りに保存する、**Then** 保存できたことが画面上で分かり、その地点が保存済みであることが予報画面に表示される
2. **Given** 「テスト沖」を保存したあとブラウザを閉じた、**When** 同じブラウザでトップ画面を開く、**Then** お気に入り一覧に「テスト沖」と、その緯度・経度が表示される
3. **Given** トップ画面のお気に入り一覧に「テスト沖」がある、**When** 「テスト沖」を選ぶ、**Then** 緯度 27.75・経度 129.05 の予報画面が表示される（緯度・経度を入力した場合と同じ予報画面）
4. **Given** お気に入りに「テスト沖」と「北の瀬」があり、「テスト沖」の予報画面を表示している、**When** 予報画面の折りたたまれたお気に入り一覧を開いて「北の瀬」を選ぶ、**Then** トップ画面に戻らずに「北の瀬」の予報画面に切り替わる
5. **Given** 予報画面でお気に入りに保存しようとしている、**When** 名前を空欄のまま保存する、**Then** 緯度・経度を名前の代わりにして（例：「27.75, 129.05」）保存される
6. **Given** お気に入りが 1 件もない、**When** トップ画面を開く、**Then** お気に入りがまだないことと、予報画面から保存できることが案内される

---

### User Story 2 - 不要になったお気に入りを削除する (Priority: P2)

もう行かなくなったポイントや、間違えて保存した地点を、お気に入り一覧から削除する。

**Why this priority**: 保存できる件数に上限があり、また一覧が不要な地点で埋まると目的の地点を探しにくくなるため、保存とセットで必要。ただし保存と呼び出し（P1）だけでも価値は成立する。

**Independent Test**: お気に入りを 2 件保存した状態で 1 件を削除し、一覧に残り 1 件だけが表示され、ブラウザを開き直しても削除した地点が戻らないことを確認すればテストできる。

**Acceptance Scenarios**:

1. **Given** お気に入り一覧に「テスト沖」と「北の瀬」がある、**When** 「テスト沖」を削除する、**Then** 一覧には「北の瀬」だけが表示され、ブラウザを開き直しても「テスト沖」は表示されない
2. **Given** 削除しようとしている、**When** 削除の操作をする、**Then** 誤操作で消さないよう、削除してよいかの確認がある
3. **Given** 保存済みの地点の予報画面を表示している、**When** その地点をお気に入りから外す、**Then** 予報画面の表示が「保存済み」から「未保存」に戻り、トップ画面の一覧からもその地点が消える

---

### User Story 3 - お気に入りの名前を変更する (Priority: P3)

保存したあとで、地点の名前をより分かりやすい名前に変える（例：空欄で保存して緯度・経度が名前になった地点に、あとから名前を付ける）。

**Why this priority**: 名前は保存時に付けられ、付け直したい場合も削除して保存し直せば代替できるため、P3 とする。

**Independent Test**: 「27.75, 129.05」という名前で保存された地点の名前を「テスト沖」に変更し、一覧の表示とブラウザを開き直したあとの表示が「テスト沖」になることを確認すればテストできる。

**Acceptance Scenarios**:

1. **Given** お気に入り一覧に「27.75, 129.05」がある、**When** 名前を「テスト沖」に変更する、**Then** 一覧の表示が「テスト沖」に変わり、緯度・経度と一覧内の並び順は変わらない
2. **Given** 名前を変更しようとしている、**When** 名前を空欄にして確定する、**Then** 緯度・経度が名前の代わりになる

---

### Edge Cases

- すでにお気に入りにある地点（小数点以下 2 桁に丸めた緯度・経度が同じ地点）を表示しているときは、予報画面に保存済みであることとその名前を表示し、同じ地点を重複して保存できないようにする
- 保存件数が上限（20 件）に達しているときに保存しようとした場合は、保存せず、不要なお気に入りを削除してから保存するよう案内する
- 名前の前後の空白は取り除く。前後の空白を除いて空になる名前は空欄として扱う
- 別の地点にすでに付けている名前と同じ名前でも、保存・名前変更できる（名前の重複は判定しない。同じ地点かどうかは緯度・経度だけで判定する）
- 名前が 30 文字を超える場合は保存せず、30 文字以内で入力するよう案内する
- 名前に記号や「<」「>」などが含まれていても、入力したとおりの文字として表示する（画面の表示や動作を崩さない）
- 予報の取得に失敗した画面や、前回の予報を警告付きで表示している画面でも、緯度・経度が有効であればお気に入りに保存できる。緯度・経度が不正で予報画面を表示できない場合は保存できない
- ブラウザの設定やプライベートブラウズなどでお気に入りを保存できない環境では、お気に入りの保存・一覧はこの環境では使えないことを表示し、緯度・経度を入力しての予報の閲覧は通常どおりできる
- 保存されているお気に入りの一部が壊れている・読み取れない場合は、読み取れた地点だけを一覧に表示し、画面全体が表示できなくなることはない
- 同じブラウザで UMIYOMI を複数のタブで開いている場合、別のタブで行った保存・削除・名前変更は、そのタブを再読み込みしたときに反映されていればよい
- お気に入り一覧には予報の数値や海況の良し悪しを表示しない（地点名と緯度・経度のみ）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 利用者は、予報画面で表示中の地点（有効な緯度・経度）をお気に入りに保存できなければならない
- **FR-002**: 保存時に、利用者は地点に 30 文字以内の名前を付けられなければならない。名前は省略でき、省略した場合は小数点以下 2 桁の緯度・経度（例：「27.75, 129.05」）を名前として表示しなければならない
- **FR-003**: お気に入りの地点は、小数点以下 2 桁に丸めた緯度・経度で扱い、同じ地点を重複して保存できてはならない
- **FR-004**: 予報画面には、表示中の地点がお気に入りに保存済みかどうかを表示し、保存済みの場合はその名前も表示しなければならない
- **FR-005**: トップ画面と予報画面の両方にお気に入り一覧を表示し、各お気に入りについて名前と緯度・経度を表示しなければならない。一覧は新しく保存したものほど上に並べる。トップ画面では、緯度・経度の入力欄のすぐ下にお気に入り一覧を（折りたたまずに）表示する。予報画面の一覧は、入力欄の近く（予報一覧より上）に最初は折りたたんだ状態で置き、利用者が開くと表示する。お気に入り一覧を閉じているあいだは、お気に入りの件数によって予報一覧が画面の下に押し出されないようにする。予報画面の一覧では、表示中の地点がどれか分かるようにする
- **FR-006**: 利用者がトップ画面・予報画面のどちらのお気に入り一覧から地点を選んでも、その地点の予報画面（緯度・経度を入力して表示した場合と同じ画面・URL）を表示しなければならない
- **FR-007**: 利用者は、お気に入りを削除できなければならない。削除の前に、削除してよいかを確認しなければならない
- **FR-016**: お気に入りの名前変更・削除はトップ画面の一覧で行う。予報画面の一覧は地点を選んで開くためだけに使い、名前変更・削除の操作は置かない（予報画面で表示中の地点をお気に入りから外す操作は FR-004 の表示とあわせて置く）
- **FR-008**: 利用者は、お気に入りの名前を変更できなければならない。名前の変更で緯度・経度と並び順は変わってはならない
- **FR-009**: お気に入りは最大 20 件まで保存でき、上限に達している場合は保存せずに、削除してから保存するよう案内しなければならない
- **FR-010**: お気に入りは、ログインなしで、利用者が使っているこの端末のブラウザに保存し、ブラウザを閉じて開き直しても残っていなければならない。お気に入りの内容を UMIYOMI のサーバーに送信・保存してはならない
- **FR-011**: お気に入りを保存できない環境でも、緯度・経度を入力しての予報の閲覧は通常どおりできなければならず、お気に入り機能がその環境では使えないことを表示しなければならない
- **FR-012**: お気に入り一覧の画面には、お気に入りはこの端末のこのブラウザだけに保存され、他の端末とは共有されないこと、ブラウザのデータを消去すると消えることを表示しなければならない
- **FR-013**: お気に入り一覧には予報の数値や海況の判定を表示してはならず、お気に入り機能のどの文言でも、安全や出航可否を断定する表現を使ってはならない
- **FR-014**: 利用者が入力した名前は、入力されたとおりの文字列として表示し、画面の表示や動作に影響を与えてはならない
- **FR-015**: お気に入りの保存・削除・名前変更の操作と一覧は、画面幅 360px 以上のスマホでページ全体が横方向にはみ出さずに使えなければならない

### Key Entities

- **お気に入り地点（Favorite Location）**: 利用者が保存した地点。名前（30 文字以内・省略可）、緯度・経度（小数点以下 2 桁に丸めた値）、保存した日時（並び順に使う）を持つ。利用者のブラウザにだけ存在し、最大 20 件
- **地点（Coordinate）**: 001-marine-forecast-view で定義した、緯度・経度の組。お気に入り地点の同一判定にも、同じ「小数点以下 2 桁に丸めた値」を使う

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: お気に入りに保存済みの地点の予報を、トップ画面を開いてから 2 回以内の操作（お気に入りを選ぶ）で表示できる
- **SC-002**: 予報画面を表示してから、名前を付けてお気に入りに保存するまでを 30 秒以内に終えられる
- **SC-003**: 保存したお気に入りは、ブラウザを閉じて開き直したあとも 100% 残っている（ブラウザのデータを消去した場合を除く）
- **SC-004**: お気に入りを保存できない環境でも、緯度・経度を入力しての予報の表示が 100% 成功する（お気に入り機能が原因で予報を表示できないケースが 0 件）
- **SC-005**: 画面幅 360px のスマホで、20 件保存した状態のお気に入り一覧から目的の地点を選んで予報を表示でき、横方向のページはみ出しが 0 件
- **SC-006**: 利用者のお気に入りの内容が UMIYOMI のサーバーに送信される通信が 0 件

## Assumptions

- 001-marine-forecast-view（緯度・経度での予報表示と、地点を特定できる予報ページの URL）が実装済みであることを前提とし、お気に入りからの表示はその予報ページを開くことで実現する
- お気に入りはログイン不要とし、端末のブラウザ内にだけ保存する（docs/SPEC.md §0 の MVP 方針）。端末間の同期、バックアップ、共有、他の利用者との共有はこの機能に含めない
- 保存件数の上限 20 件は、よく行くポイントを登録する用途に十分で、スマホの一覧で探しにくくならない値として仮置きしている。名前の上限 30 文字は、スマホ幅の一覧で 1〜2 行に収まる長さとして仮置きしている
- 一覧の並び順は新しく保存したものが上とし、利用者による並べ替え・グループ分け・検索は持たない
- お気に入りには地点（名前・緯度・経度）だけを保存し、予報データは保存しない。オフライン閲覧は MVP の範囲外（アプリ化のときに対応する）
- 予報画面にもお気に入り一覧を置くのは、出航前に複数のポイントを順番に見比べる使い方で、トップ画面に戻らずに地点を切り替えられるようにするため。予報画面を一覧の編集操作で煩雑にしないよう、名前変更・削除はトップ画面に集める
- 地図からの地点指定、現在地からの保存、お気に入り地点ごとの通知はこの機能に含めない
