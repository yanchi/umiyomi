# Contract: 入力欄・URL・メッセージ

**Feature**: 003-coordinate-input-support | **Date**: 2026-10-05

ルートは 001 の [web-routes.md](../../001-marine-forecast-view/contracts/web-routes.md) のまま（`GET /`・`GET /forecast`）。新しいルート・API は作らない。
この文書は、`GET /forecast` の Query とレスポンスの変更、入力フォームの構成、メッセージの文言、Twig と JavaScript の取り決めを定める。画面・URL 設計は人間のレビュー対象。

## `GET /forecast` の変更

### Query

| パラメータ | 必須 | 形式 | 例 |
|---|---|---|---|
| `lat` | ○ | 緯度。十進数・度分・度分秒・「緯度, 経度」の 1 行（[data-model.md](../data-model.md) の「受け付ける表記」）。100 文字まで | `27.75` / `27°45.0'N` / `27.75, 129.05` |
| `lon` | ○ | 経度。同上。`lat` に 1 行の文字列があれば空でよい | `129.05` / `129°03.0'E` / （空） |
| `ignored` | — | `lat` または `lon`。リダイレクト先でだけ付く（FR-004 の通知）。それ以外の値は無視する | `lon` |

### Response

| 状況 | Status | 本文・ヘッダー |
|---|---|---|
| 入力が有効で、`lat` / `lon` が正規形（`%.2f`。例：`27.75`） | 001 と同じ（200 / 503 / 429） | 予報画面。`ignored` があれば通知を出す |
| 入力が有効で、正規形でない（十進数以外・1 行の文字列・`27.7500`・`27.755` など） | **303** | `Location: /forecast?lat=<正規形>&lon=<正規形>[&ignored=lat\|lon]`。予報は取得しない（回数制限にも数えない） |
| 入力エラー | 422 | 入力した文字列を入力欄に残し、欄ごとのメッセージを出す（001 と同じ） |

- 001 の「入力された文字列はそのまま URL に残る（正規化した URL へのリダイレクトはしない）」を、この機能で上記に変更する（[research R5](../research.md#r5-読み取った地点を-url入力欄に反映する方法fr-010)）
- 正規形の URL を開いたときはリダイレクトしないので、リダイレクトが繰り返されることはない
- 正規形は `Angle::toCanonicalString()`：小数点以下 2 桁、`-0.00` は `0.00`、`+` は付けない

例：

| 入力（緯度欄 / 経度欄） | 結果 |
|---|---|
| `27.75` / `129.05` | 200（従来どおり） |
| `27.7500` / `129.05` | 303 → `?lat=27.75&lon=129.05` |
| `27.75, 129.05` / （空） | 303 → `?lat=27.75&lon=129.05` |
| `35.10, 139.20` / `129.05` | 303 → `?lat=35.10&lon=139.20&ignored=lon` |
| `27°45.0'N` / `129°03.0'E` | 303 → `?lat=27.75&lon=129.05` |
| `27°45.3'` / `129.05` | 303 → `?lat=27.76&lon=129.05`（FR-023） |
| `129.05, 27.75` / （空） | 422（`swapped_order`） |
| `27°75'N` / `129.05` | 422（`minute_second_range`） |

## 入力フォーム（トップ画面・予報画面で共通、`forecast/_form.html.twig`）

上から順に：

1. 緯度の入力欄（ラベル「緯度」、プレースホルダ「例：27.75」）と、その欄のエラー
2. 経度の入力欄（ラベル「経度」、プレースホルダ「例：129.05」）と、その欄のエラー
3. 「予報を表示」ボタン
4. **現在地**（`hidden` 付きで出力。JavaScript が使える条件のときだけ表示。research R8）
   - 「現在地を入力」ボタン（`type="button"`）
   - 状態のメッセージ（`role="status"`）
   - 案内（FR-019）
5. **入力の案内**（FR-012。常に表示）
6. **入力欄が表示中の地点と異なるときの案内**（FR-021。予報画面で予報一覧があるときだけ出力。`hidden` 付き）

入力欄の属性（FR-020、research R7）：`type="text"`、`autocomplete="off"`、`autocapitalize="off"`、`autocorrect="off"`、`spellcheck="false"`。`inputmode` は付けない。
エラーがあるときは従来どおり `aria-invalid="true"` と `aria-describedby` を付ける。

## 予報画面の構成の変更（001・002 からの差分）

1. タイトルと入力フォーム（上記）
2. **入力の通知**（`ignored` があるときだけ。`role="status"`）
3. お気に入り一覧（折りたたみ。002 のまま）
4. 以降は 002 のまま。ただし保存パネルに **保存される地点** を表示する（FR-025）

## メッセージ

### 入力の案内（FR-012。フォームの下に常に表示）

> 十進数（27.75）のほか、「緯度, 経度」の貼り付け（27.75, 129.05）、度分（27°45.0'N）、度分秒（27°45'00"N）で入力できます。南緯・西経はマイナスの値にするか、S・W を付けてください。

### 欄ごとのエラー（`{欄}` は「緯度」または「経度」、`{範囲}` は「-90〜90」または「-180〜180」）

読み取れない入力の文言の末尾には、共通の入力例「入力例：27.75 / 27.75, 129.05 / 27°45.0'N / 27°45'00"N」を付ける（FR-011、US3-1）。下表で「＋例」と書いたもの。

| 原因 | 文言 |
|---|---|
| `empty` | {欄}を入力してください |
| `too_long` | {欄}の入力が長すぎます。100 文字以内で入力してください |
| `unreadable` | {欄}を読み取れませんでした。＋例 |
| `url` | リンクからは地点を読み取れません。地図アプリで緯度・経度をコピーして貼り付けてください |
| `conflicting_directions` | {欄}に方角の文字が複数あります。N・S・E・W のどれか 1 つにしてください |
| `sign_and_direction` | {欄}にマイナス記号と方角の文字の両方があります。どちらか一方にしてください |
| `degree_not_integer` | 度分・度分秒で入力するときは、度を整数にしてください（例：27°45.0'） |
| `minute_second_range` | 分・秒は 0 以上 60 未満で入力してください |
| `axis_mismatch`（緯度欄） | 緯度には N（北緯）か S（南緯）を付けてください。E・W は経度に使います |
| `axis_mismatch`（経度欄） | 経度には E（東経）か W（西経）を付けてください。N・S は緯度に使います |
| `out_of_range` | {緯度 or 経度}は {範囲} の範囲で入力してください（1 行の文字列のときは、範囲外の方の名前を出す。両方とも範囲外なら緯度の文言だけを出す） |
| `too_many_values` | 緯度と経度の 2 つだけを入力してください。＋例 |
| `unitless_degree_minutes` | 度分で入力するときは、度と分の記号を付けてください（例：27°45.0' 129°03.0'） |
| `pair_direction_mixed` | 緯度と経度の両方に方角の文字を付けるか、両方とも付けずに入力してください |
| `pair_same_axis` | 緯度（N・S）と経度（E・W）を 1 つずつ入力してください |
| `swapped_order` | 緯度と経度の順序が逆になっている可能性があります。「緯度, 経度」の順で入力してください（例：27.75, 129.05） |
| `both_pairs` | 「緯度, 経度」はどちらか一方の欄だけに入力してください（両方の欄に出す） |

### 入力の通知（FR-004。`ignored` のとき）

| `ignored` | 文言 |
|---|---|
| `lon` | この地点は緯度欄の「緯度, 経度」から読み取りました。経度欄に入っていた値は使っていません |
| `lat` | この地点は経度欄の「緯度, 経度」から読み取りました。緯度欄に入っていた値は使っていません |

### 現在地（`role="status"` の領域。1 つだけ表示）

| 状態 | 文言 |
|---|---|
| 取得中 | 現在地を取得しています… |
| 入力した | 現在地を入力しました。「予報を表示」を押すと予報を表示します |
| 拒否された | 位置情報の利用が許可されなかったため、現在地を入力できませんでした。緯度・経度を入力すると予報を表示できます |
| 取得できなかった（時間切れ・取得不能） | 現在地を取得できませんでした。もう一度試すか、緯度・経度を入力すると予報を表示できます |
| 取得中に入力欄が変わった | 入力欄が変更されたため、取得した現在地は入力していません |

案内（FR-019。ボタンの近くに常に表示）：

> 現在地が陸地や港の内側の場合、波・うねりの予報が得られないことや、沖の海況と異なることがあります。必要に応じて沖側の地点を入力してください。

### 入力欄が表示中の地点と異なるとき（FR-021）

> 入力欄の地点の予報はまだ表示していません。表示中の一覧は 北緯 27.75° / 東経 129.05° の予報です。「予報を表示」を押すと、入力欄の地点の予報に切り替わります。

### 保存パネルの地点（FR-025）

> 保存される地点：北緯 27.75° / 東経 129.05°（表示中の地点）

### 文言の制約

- 安全・出航可否の断定（「安全です」「出航できます」「問題ありません」等）を含めない（原則 IV）。Functional Test で確認する
- 文言はすべて Twig（または ViewModel）に置く。JavaScript は文言を組み立てず、`hidden` の切り替えだけを行う

## Twig と JavaScript の取り決め

| 要素 | 属性 | 意味 |
|---|---|---|
| `<form>` | `data-coordinate-input` | 初期化の対象 |
| 緯度・経度の `<input>` | `data-coordinate-field="latitude"` / `"longitude"` | 現在地を入れる欄・食い違いを判定する欄 |
| 現在地の領域 | `data-current-location`、`hidden` | 条件を満たすとき JavaScript が `hidden` を外す |
| 現在地のボタン | `data-current-location-action="fill"` | 取得中は `disabled` |
| 現在地のメッセージ | `data-current-location-message="loading" \| "filled" \| "denied" \| "failed" \| "edited"`、`hidden` | 1 つだけ表示する |
| 食い違いの案内 | `data-coordinate-stale-notice`、`hidden` | `value !== defaultValue` の欄があれば表示（research R9） |

- JavaScript が動かない環境では、現在地の領域と食い違いの案内は `hidden` のまま（FR-018。FR-021 は JavaScript が動かない環境では必須としない）
- JavaScript は入力欄の文字列を座標として読まない（読み取りはサーバーだけ。spec Assumptions）
